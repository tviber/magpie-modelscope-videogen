# Privacy and data handling

## What runs where

- The Magpie plugin sends tool arguments only to the configured WAN service URL. By default this is `http://127.0.0.1:8765`.
- The Python service reads input images only from directories explicitly listed in `WAN_MEDIA_ROOTS`, then sends the prompt and resized frame images to ModelScope through the configured signed-in browser session.
- The service downloads the resulting video from the provider and serves it from its loopback HTTP endpoint.
- This package has no analytics, telemetry, or background upload service.

ModelScope receives the prompt, style/negative-prompt fields if supplied, and frame images because it performs the generation. Do not submit material you do not want sent to ModelScope.

## Local data

The service stores prompts, copied input frames, job state, provider task identifiers, bounded allowlisted failure details, timestamped job events/account reassignments, and completed videos in its application data directory. It sets the directory permissions to owner-only and files to owner read/write where supported. SQLite stores stable account IDs, salted login fingerprints and their local salt. A browser launched by **登录新账号** uses an isolated profile under `browser-profiles`; this contains ModelScope's normal browser session data (including cookies) and must be treated as credentials. The service stores its local CDP mapping in a private registry alongside it. Do not copy or publish this directory. Use generic account IDs such as `account-1`, since they are visible in tool responses. Keep the entire database and browser-profiles directory together when migrating so identity checks remain effective. Signed provider download URLs may remain in unfinished job records until refreshed or completed; treat the whole data directory as private.

Status responses do not include absolute input or output paths. They now include prompts, project/shot labels, input basenames/dimensions and relative frame-preview routes. The authenticated configuration endpoint and path-validation errors intentionally disclose allowed root directories to help prepare files. Account endpoints disclose verified display names, configured IDs and available magicube balances from an in-memory cache; ModelScope cookies and raw immutable login IDs are not returned. Magpie stores the connected account label and configured ID in its own sign-in store. The managed Login flow uses Magpie's existing native sign-in dialog and opens a visible isolated Chrome window for official-site SMS/slider verification. There is no custom frontend, localhost login webpage, screenshot stream or input relay. Magpie polls authenticated task status and receives only the verified account ID and label. After verification, session cookies are carried in memory to headless Chrome using the same private profile, and identity is checked again. Login credentials are never returned in URLs or logged. Only provider-verified identity completes login. Magpie's per-account Settings → Remove control removes only the selected saved sign-in. It does not delete the independent WAN service's browser profile, account queue or video history. Loading the plugin alone does not sign accounts back in. The result tool performs an authenticated download to the plugin host's `~/.magpie-wan/results` (or its configured `outputDir`) and returns that absolute local artifact path and file URL to the calling agent. This intentionally reveals the artifact location, which may include a home-directory name. Result bundles also contain input-frame PNGs, a JSON manifest and an escaped, script-free HTML preview. A background completion watcher persists task IDs and downloads bundles for plugin-submitted jobs; its Magpie completion message includes the prompt, frame names and preview path and may appear in Magpie logs. Set `watchJobs:false` to disable this watcher. Completed copies remain until deleted; failed partial copies are removed. The long-lived service token stays in request headers, never in result URLs. Service logs avoid printing prompts, raw login identities and browser endpoints. Path-validation errors name the allowed directories. Explicit frame staging reads only the files provided to the tool and copies them to a private subdirectory within an allowed root; successful staging copies remain until deleted. The Python service still refuses inputs outside its roots. Local CDP endpoints and the bearer token are read from environment variables and local plugin options; do not commit them to a repository or paste them into public issues.

Only exact official ModelScope HTTPS page hosts are accepted. API calls use absolute trusted URLs through the browser context's HTTP client with redirects disabled. Upload destinations are restricted to official ModelScope HTTPS hosts and bucket-specific Alibaba OSS HTTPS endpoints, with upload redirects disabled.

## Package contents

The standalone package contains only the generic WAN adapter, Magpie tools, package metadata, and documentation. Tests and CI configuration remain in the source repository. The distribution does not include unrelated projects, media, user configuration, browser profiles, account data, or credentials. Review the package file list before publishing a release.
